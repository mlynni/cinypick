# Ультракороткий код сесії (Бінарне пакування ID + TMDb-ключ)

Скорочення довжини коду сесії у **10–15 разів** шляхом переходу від текстового JSON до компактного бінарного протоколу (`K2.`), який зберігає лише числовий `tmdbId`, 1 байт статусу й оцінки на кожен фільм та бінарно спакований ключ TMDb API, автоматично підтягуючи постери й назви після вставки на новому пристрої.

### User Review & Critical Decisions

> [!IMPORTANT]
> Усі ваші відповіді враховано в оновленій архітектурі коду сесії:

- **Бінарне пакування замість тексту**: Замість збереження назв, описів та посилань на постери кожен фільм займає лише **4 байти** (Varint `tmdbId` + 1 байт бітової маски для статусу «Обрано» / «Переглянуто» та оцінки `0.5–5.0 ★`).
- **Вбудований ключ TMDb API (16 байтів)**: Стандартний 32-символьний HEX-ключ TMDb стискається рівно у 16 сирих байтів всередині коду. При вставці коду сесії на чистій сторінці GitHub Pages ключ автоматично підключається і зберігається в налаштуваннях.
- **Автоматичне підвантаження з TMDb**: Під час імпорту коду сесії застосунок паралельно завантажує свіжі постери, двомовні назви (UA / EN), роки та рейтинги для всіх ID фільмів із TMDb.

---

### 1. Overview & Core Concept

- **Що це дає**: Колекція з 15–20 фільмів разом із ключем TMDb API тепер вміщується в один охайний короткий рядок (~80–110 символів замість 1500+ символів).
- **Повна автономність на новому пристрої**: На сторінці GitHub Pages не потрібно навіть окремо вводити ключ TMDb — достатньо вставити один короткий код сесії, і сайт сам збереже ключ та підтягне всі постери й списки.

---

### 2. User Experience & Visual Design

- **Користувацький сценарій**:
  1. У вікні **Налаштування** користувач натискає **«Скопіювати код сесії»** — миттєво формується короткий рядок формату `K2....` (із вбудованим поточним ключем TMDb та всіма ID фільмів).
  2. На новому сайті (наприклад, GitHub Pages) користувач вставляє цей короткий код у поле та натискає **«Завантажити»**.
  3. Кнопка показує індикатор підвантаження метаданих із TMDb (`Завантаження...`), автоматично зберігає ключ TMDb API (секція ключа одразу стає «Підключено») і плавно відображає всі фільми у рулетці та списку бажаного з їхніми постерами, чорно-білими статусами й оцінками.

---

### 3. Key Product Decisions & Trade-Offs

- **Рішення 1: Побітове пакування статусу та зіркової оцінки в 1 байт**
  - *Обраний підхід*: Один байт (`0..255`) кодує одночасно статус фільму (біти `0–1`: `0` — у рулетці, `1` — обрано, `2` — переглянуто) та оцінку користувача з кроком `0.5` (біти `2–5`: значення `userRating * 2` від `0` до `10`).
  - *Чому*: Це дозволяє взагалі не витрачати місце на JSON-ключі (`"isChosen":true,"userRating":4.5` — це 32 байти тексту, а в бінарному форматі — рівно **1 байт**).

- **Рішення 2: Стиснення 32-символьного ключа TMDb у 16 байтів**
  - *Обраний підхід*: Оскільки ключ TMDb v3 складається з шістнадцяткових символів (`0-9a-f`), кожні 2 символи пакуються в 1 байт. Якщо використовується довший Read Token, він стискається потоковим `deflate-raw`.
  - *Чому*: Ключ займає мінімум символів у фінальному рядку й дозволяє миттєво виконати запити до TMDb на новому браузері.

---

### 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **Структура бінарного пакета `K2.` та потік відновлення**:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Бінарний пакет сесії (K2.<Base64URL>)                │
│  [Header: 1B] + [TMDb Key: 16B HEX] + [Pool Count] + [Wishlist Count]   │
│  + Для кожного фільму: [Varint tmdbId (2-4B)] + [MetaByte (1B):         │
│     біти 0..1 = статус (0/1/2), біти 2..5 = оцінка (0..10)]             │
└───────────────────┬─────────────────────────────────┬───────────────────┘
                    │ Копіювання                      │ Завантаження
                    ▼                                 ▼
┌───────────────────────────────────┐ ┌───────────────────────────────────┐
│   encodeSessionHash(pool, wish,   │ │   hydrateSessionFromHash(code)    │
│                     apiKey)       │ │ 1. Розпаковка ключа TMDb та ID    │
│ • Пакує всі фільми у компактний   │ │ 2. Автозбереження ключа TMDb      │
│   Uint8Array та Base64URL         │ │ 3. Паралельні запити /movie/{id}  │
└───────────────────────────────────┘ │    (UA + EN) і відновлення списків│
                                      └───────────────────────────────────┘
```

- **Зворотна сумісність**: Декодер підтримуватиме як новий короткий формат `K2.`, так і попередній `KR1.`, щоб жодні раніше скопійовані коди не видавали помилку.
