# Синхронізація списків через компактний код сесії (Хеш)

Додавання можливості миттєво переносити всі додані фільми, їхні статуси («Обрано» / «Переглянуто»), власні оцінки (0.5–5.0 ★) та список бажаного між різними версіями сайту (наприклад, із AI Studio на GitHub Pages) за допомогою одного стисненого текстового коду сесії.

### User Review & Critical Decisions

> [!IMPORTANT]
> Усі уточнення з попереднього кроку враховано в архітектурі плану:

- **Підтверджений формат перенесення**: Використовується виключно текстовий код сесії (хеш) для швидкого копіювання в буфер обміну та вставки без створення зайвих файлів.
- **Підтверджений склад даних**: Код сесії містить список фільмів у рулетці (разом зі статусами «У рулетці», «Обрано», «Переглянуто» та особистими зірковими оцінками) і список бажаного.
- **Підтверджене розташування в інтерфейсі**: Окремий компактний блок синхронізації всередині вікна налаштувань.
- **Режим імпорту за замовчуванням**: При вставці коду сесії нові фільми розумно об'єднуються з поточними (або оновлюють статуси й оцінки вже наявних фільмів за їхнім ідентифікатором), щоб випадково не втратити вже додані на новому сайті фільми.

---

### 1. Overview & Core Concept

- **Що це робить**: Генерує стиснений текстовий код сесії (`KR1-...`), який містить увесь пул фільмів користувача, їхні статуси, оцінки та список бажаного, і дозволяє відновити ці дані в один клік на будь-якому іншому пристрої чи домені (зокрема на GitHub Pages).
- **Для кого і в якому сценарії**: Для користувача, який сформував колекцію фільмів у поточному середовищі й хоче миттєво перенести її на власну сторінку GitHub Pages або поділитися добіркою з друзями.
- **Ключова цінність**: Повна незалежність від серверної бази даних — усі постери, двомовні назви, роки, рейтинги, чорно-білі статуси та оцінки відновлюються миттєво після вставки коду.

---

### 2. User Experience & Visual Design

- **Користувацький сценарій**:
  1. Користувач відкриває вікно **Налаштування** (іконка шестерні на лівій панелі).
  2. У новому компактному розділі **«Код сесії (Перенесення списку)»** натискає кнопку **«Скопіювати код сесії»** — стиснений хеш поточної колекції автоматично копіюється в буфер обміну, а кнопка показує підтвердження з кількістю збережених фільмів.
  3. На сторінці GitHub Pages користувач відкриває **Налаштування**, вставляє скопійований хеш у компактне поле вводу та натискає **«Завантажити»**.
  4. Фільми у рулетці та список бажаного одразу з'являються з плавною анімацією `fade-in`, зберігаючи всі постери, чорно-білі позначки («Переглянуто» / «Обрано») та виставлені зірки.
- **Візуальний стиль та інтеграція**:
  - *Естетика*: Мінімалістичний монохромний блок із чітким групуванням, що гармонійно продовжує дизайн секції TMDb API у вікні налаштувань.
  - *Кольорова палітра*: Використання системних змінних `--bg-subcard`, `--border-subtle`, `--text-main`, `--accent-primary` та смарагдового індикатора успішного копіювання/відновлення (`emerald-400`).
  - *Типографіка*: Заголовок секції у стилі `11px uppercase tracking-wider font-bold`, поле коду з моноширинним відображенням хешу та компактні кнопки дій.
- **Інтерактивний зворотний зв'язок**:
  - Миттєвий індикатор «Скопійовано!» на 2 секунди після копіювання коду.
  - Повідомлення про результат імпорту (наприклад: «Завантажено: 12 фільмів, 5 у списку бажаного») або чітке повідомлення про помилку, якщо вставлений текст пошкоджений.

---

### 3. Key Product Decisions & Trade-Offs

- **Рішення 1: Вбудовані міні-метадані + Deflate-стиснення замість збереження лише числових ID**
  - *Обраний підхід*: Кожен фільм серіалізується у компактний кортеж (числовий `tmdbId`, українська та англійська назви, рік, короткий шлях до постера без базового домену, базовий рейтинг, прапорець статусу `0 | 1 | 2` та особиста оцінка), після чого масив стискається алгоритмом `deflate-raw` (`CompressionStream`) у формат Base64URL із префіксом `KR1.`.
  - *Чому*: Якби код містив лише числові `tmdbId`, то на новому сайті без попередньо введеного TMDb API-ключа фільми взагалі не змогли б завантажитися. А завдяки стисненим міні-метаданим усі постери, назви, статуси та оцінки з'являються **миттєво навіть без API-ключа**, а повні деталі (актори, режисер, трейлер) автоматично довантажуються при відкритті картки фільму.
  - *Альтернативи*: Звичайний необроблений JSON у Base64 був відхилений, оскільки він у 5–8 разів довший через повторювані URL-адреси та текстові описи.

- **Рішення 2: Безпечне об'єднання списків при імпорті**
  - *Обраний підхід*: Імпорт із коду сесії додає нові фільми та оновлює статуси/оцінки збігів за `id`, не видаляючи ті фільми, які користувач вже встиг додати на новому місці.
  - *Чому*: Запобігає випадковій втраті даних під час синхронізації між двома вкладками або пристроями.

### 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **Архітектура та потік даних**:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        App State (localStorage)                         │
│   • myMovies (Фільми + isChosen / isWatched / userRating)               │
│   • wishlistMovies (Список бажаного + userRating)                       │
└───────────────────┬─────────────────────────────────┬───────────────────┘
                    │ Експорт                         │ Імпорт (Merge)
                    ▼                                 ▲
┌───────────────────────────────────┐ ┌───────────────────────────────────┐
│     Session Hash Serializer       │ │     Session Hash Deserializer     │
│ 1. Відбір компактних кортежів     │ │ 1. Перевірка префікса "KR1."      │
│    [id, tmdbId, uk, en, year,     │ │ 2. Base64URL -> Decompression     │
│     posterSlug, score, status, ★] │ │    (або фолбек для чистого B64)   │
│ 2. Deflate-raw CompressionStream  │ │ 3. Відновлення об'єктів MovieItem │
│ 3. Base64URL з префіксом "KR1."   │ │    із постерами, статусами та ★   │
└───────────────────┬───────────────┘ └───────────────┬───────────────────┘
                    │                                 │
                    ▼                                 ▲
┌─────────────────────────────────────────────────────────────────────────┐
│               SettingsPopover — Блок «Код сесії»                        │
│  [ Скопіювати код сесії (N) ]   [ Поле вставки хешу... ] [ Завантажити ]│
└─────────────────────────────────────────────────────────────────────────┘
```

- **Структура компактного запису фільму**:
  - Статус кодується одним числом: `0` — активний у рулетці, `1` — обраний (`isChosen`), `2` — переглянутий (`isWatched`).
  - Шлях до постера зберігається лише як суфікс файлу (наприклад, `/xYz123.jpg`), а при декодуванні автоматично відновлюється до повного `https://image.tmdb.org/t/p/w780/xYz123.jpg`.
- **Мапінг станів та інтерактивності**:
  - Кнопка **«Скопіювати код сесії»** викликає асинхронну функцію генерації хешу, записує рядок у `navigator.clipboard.writeText` (а також підставляє його у поле для наочності) і показує статус успіху.
  - Поле вставки коду сесії та кнопка **«Завантажити»** валідують префікс і цілісність даних, розпаковують обидва списки (`myMovies` та `wishlistMovies`), передають їх у обробник в основному компоненті застосунку та відображають підсумок імпорту.
